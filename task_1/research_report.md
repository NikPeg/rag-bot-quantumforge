# Задание 1: Исследование моделей и инфраструктуры

## Введение

Данный документ содержит анализ различных компонентов для построения RAG-бота для компании QuantumForge Software. Цель исследования — выбрать оптимальный стек технологий с учётом требований компании: обработка ~18,000 Markdown файлов, ~3,000 страниц Confluence, ~250 PDF-спецификаций с постоянным приростом ~400 страниц в месяц.

## 1. Сравнение LLM-моделей

### 1.1 Локальные модели (Hugging Face)

#### Популярные варианты:
- **Llama 2/3** (7B, 13B, 70B параметров)
- **Mistral 7B**
- **Phi-2/3** (Microsoft)
- **Qwen2** (Alibaba)

#### Преимущества:
- ✅ **Конфиденциальность**: данные не покидают инфраструктуру компании
- ✅ **Предсказуемая стоимость**: нет платы за токены после развёртывания
- ✅ **Полный контроль**: можно дообучать и модифицировать
- ✅ **Независимость от интернета**: работа в изолированных сетях

#### Недостатки:
- ❌ **Высокие требования к инфраструктуре**: нужны GPU (минимум 16GB VRAM для 7B моделей)
- ❌ **Скорость**: медленнее облачных решений на CPU, требует GPU для приемлемой скорости
- ❌ **Качество**: локальные модели 7B-13B часто уступают GPT-4/YandexGPT в сложных задачах
- ❌ **Сложность развёртывания**: требуется настройка CUDA, оптимизация памяти
- ❌ **Стоимость владения**: покупка и обслуживание GPU-серверов

#### Оценка качества:
- **Llama 3 8B**: хорошее качество для базовых задач, но уступает GPT-4
- **Mistral 7B**: отличный баланс качества и размера
- **Phi-3**: компактная модель с хорошим качеством для простых задач

#### Скорость работы:
- **CPU**: 1-5 токенов/сек (неприемлемо для продакшена)
- **GPU (RTX 3090)**: 20-50 токенов/сек для 7B моделей
- **GPU (A100)**: 100+ токенов/сек

#### Стоимость владения:
- **Сервер с GPU (RTX 3090)**: ~$2,000-3,000 единоразово + ~$200-300/мес (электричество, охлаждение)
- **Облачный GPU (Yandex Cloud)**: ~$1-2/час для инстанса с GPU
- **Для 24/7 работы**: ~$700-1,400/мес

## 3. Сравнение векторных баз данных

### 3.1 FAISS (Facebook AI Similarity Search)

#### Характеристики:
- **Тип**: Библиотека для поиска похожих векторов
- **Хранение**: В памяти или на диске
- **Индексы**: L2, Inner Product, различные варианты (IVF, HNSW, etc.)

#### Преимущества:
- ✅ **Скорость**: очень быстрый поиск (микросекунды для миллионов векторов)
- ✅ **Простота**: легко интегрируется, минимальные зависимости
- ✅ **Гибкость**: множество алгоритмов индексации
- ✅ **Бесплатно**: open-source
- ✅ **Легковесность**: можно встроить в приложение

#### Недостатки:
- ❌ **Только векторы**: нет встроенной поддержки метаданных (нужно хранить отдельно)
- ❌ **Нет персистентности по умолчанию**: нужно самостоятельно сохранять/загружать
- ❌ **Нет распределённости**: работает на одном узле
- ❌ **Сложность обновлений**: пересборка индекса при больших изменениях

#### Скорость поиска:
- **HNSW индекс**: ~1-5 мс для поиска в 1M векторов
- **IVF индекс**: ~5-20 мс для поиска в 1M векторов

#### Скорость индексации:
- **HNSW**: ~10-30 секунд для 1M векторов (384 dim)
- **IVF**: ~5-15 секунд для 1M векторов

#### Сложность внедрения:
- ⭐⭐⭐⭐ (простое, но требует ручной работы с метаданными)

#### Стоимость владения:
- **Инфраструктура**: только сервер для хранения
- **Для 200,000 векторов (384 dim)**: ~300 МБ RAM
- **Сервер**: минимальные требования (2-4 GB RAM достаточно)

### 3.2 ChromaDB

#### Характеристики:
- **Тип**: Векторная БД с поддержкой метаданных
- **Хранение**: В памяти или на диске (SQLite)
- **Индексы**: HNSW (по умолчанию)

#### Преимущества:
- ✅ **Метаданные**: встроенная поддержка метаданных (фильтрация, группировка)
- ✅ **Персистентность**: автоматическое сохранение на диск
- ✅ **Простота API**: удобный Python API
- ✅ **Встроенная поддержка LangChain**: отличная интеграция
- ✅ **Коллекции**: организация данных по коллекциям
- ✅ **Бесплатно**: open-source

#### Недостатки:
- ❌ **Медленнее FAISS**: дополнительный overhead на метаданные
- ❌ **Меньше гибкости**: меньше вариантов индексации
- ❌ **Нет распределённости**: работает на одном узле (в open-source версии)

#### Скорость поиска:
- **HNSW индекс**: ~5-15 мс для поиска в 1M векторов

#### Скорость индексации:
- **HNSW**: ~20-40 секунд для 1M векторов

#### Сложность внедрения:
- ⭐⭐⭐⭐⭐ (очень простое, готовые интеграции)

#### Стоимость владения:
- **Инфраструктура**: только сервер для хранения
- **Для 200,000 векторов + метаданные**: ~500 МБ RAM + ~200 МБ на диске
- **Сервер**: минимальные требования (2-4 GB RAM достаточно)

- **Задержки сети**: Дополнительная latency при работе через международные сервисы

### 7.4 Рекомендации по митигации рисков

1. **Использовать несколько моделей**: Настроить fallback на альтернативные модели
2. **Мониторинг доступности**: Регулярно проверять доступность выбранных моделей
3. **Локальные резервы**: Рассмотреть возможность локальных моделей для критических задач
4. **Документирование**: Ведение логов доступности для анализа трендов
