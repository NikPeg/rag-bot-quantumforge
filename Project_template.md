## Задание 2. Подготовка базы знаний

### Отчёт

База знаний создана на основе вики Hazbin Hotel с полной заменой всех оригинальных терминов на вымышленные.

### Выбранная предметная область

**Источник**: Вики Hazbin Hotel (https://hazbinhotel.fandom.com)

**Обоснование выбора**:
- Популярный фандом, который точно присутствует в обучающих данных LLM
- Богатая вселенная с множеством персонажей, локаций и концепций
- Достаточный объём контента для создания полноценной базы знаний

### Результаты скачивания и обработки

**Скачано страниц**: 173 документа из вики
- Персонажи (Characters): 50 страниц
- Локации (Locations): 50 страниц
- Эпизоды (Episodes): 49 страниц
- Объекты (Objects): 15 страниц
- Организации (Organizations): 19 страниц
- События (Events): 6 страниц

**Обработано документов**: 174 файла (включая README)
- Формат: Markdown (.md)
- Общий объём: ~1.66 млн символов текста
- Все документы очищены от HTML и лишнего форматирования

### Словарь замен

**Файл**: `knowledge_base/terms_map.json`

**Категории замен**:
- **Персонажи** (58 терминов): Charlie → Zara, Vaggie → Mira, Alastor → Korax, Angel Dust → Silk Shadow и т.д.
- **Локации** (25 терминов): Hazbin Hotel → Twilight Manor, Hell → Netherrealm, Heaven → Celestia и т.д.
- **Концепции** (25 терминов): Extermination → Purge, Sinners → Fallen, Angels → Stokers и т.д.
- **Организации** (8 терминов): The Overlords → The Sovereigns, Exterminators → Purifiers и т.д.
- **Предметы** (6 терминов): Angelic Steel → Stoker Steel, Holy Water → Divine Water и т.д.
- **Серии** (1 термин): Helluva Boss → Nether Agents

**Всего замен**: 123+ термина

**Особенности замены**:
- Использованы нейтральные термины, не связанные с оригинальным лором (например, "Stoker" вместо "Seraph" для ангелов)
- Избеганы конфликты с существующими персонажами из других фан-вики
- Сохранена логика и стиль мира для читаемости текстов

### Скрипты обработки

1. **`download_wiki.py`** — автоматическое скачивание страниц вики
   - Использует Fandom API для получения списка страниц
   - Парсит HTML и извлекает чистый текст
   - Сохраняет в формате Markdown

2. **`replace_terms.py`** — замена всех терминов согласно словарю
   - Обрабатывает формы с апострофами (Charlie's → Zara's)
   - Сортирует замены по длине для избежания частичных замен
   - Поддерживает регистронезависимую замену

3. **`create_wordcloud.py`** — создание облака слов для проверки
   - Визуализация частоты терминов
   - Проверка на наличие незаменённых оригинальных терминов
   - Результат: `wordcloud.png`

## Задание 3. Создание векторного индекса базы знаний

### Отчёт

Векторный индекс базы знаний успешно создан с использованием ChromaDB и модели эмбеддингов `sentence-transformers/all-MiniLM-L6-v2`.

### Выбранная модель эмбеддингов

**Модель**: `sentence-transformers/all-MiniLM-L6-v2`

**Характеристики**:
- **Размерность эмбеддингов**: 384
- **Размер модели**: ~22 МБ
- **Скорость**: ~5-10 мс на CPU для короткого предложения
- **Репозиторий**: https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2
- **Обоснование**: Выбрана согласно рекомендациям из задания 1 — оптимальный баланс качества, скорости и размера для локального использования

### Параметры разбиения на чанки

- **Размер чанка**: 500 токенов (в диапазоне 500-1000 токенов, как рекомендовано в задании)
- **Overlap**: 100 токенов (20% перекрытия для сохранения контекста)
- **Разделители**: `\n\n`, `\n`, `. `, ` `, `""` (RecursiveCharacterTextSplitter)
- **Метод**: Использован `RecursiveCharacterTextSplitter` из LangChain для логического разбиения текста

### Метаданные

Каждый чанк содержит следующие метаданные для трассировки источников:
- `source`: полный путь к исходному файлу
- `file_name`: имя файла
- `chunk_index`: порядковый номер чанка в документе (начиная с 0)
- `total_chunks`: общее количество чанков в документе

### Векторная БД

**ChromaDB** — выбрана согласно рекомендациям из задания 1:
- ✅ Встроенная поддержка метаданных (критично для трассировки источников)
- ✅ Автоматическая персистентность на диск
- ✅ Простая интеграция с LangChain
- ✅ Достаточная производительность для текущего объёма данных

### Результаты индексации

**База знаний**:
- Использована база знаний из задания 2 (Hazbin Hotel с заменёнными терминами)
- Обработано: ~347 документов в формате Markdown
- Исключены: папка `raw` и служебные файлы

**Процесс индексации**:
1. Загрузка всех `.md` документов из `knowledge_base/`
2. Разбиение документов на чанки с сохранением метаданных
3. Генерация эмбеддингов для каждого чанка
4. Сохранение индекса в ChromaDB на диск

**Статистика** (результаты первого запуска):
- Количество обработанных документов: **173 документа** из базы знаний задания 2
- Количество созданных чанков: **4509 чанков**
- Время индексации: **30.39 секунд**
- Средняя скорость обработки: **148.35 чанков/сек**

Каждый запрос возвращает топ-3 наиболее релевантных чанка с оценкой релевантности (score) и метаданными.
